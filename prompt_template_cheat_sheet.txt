STAGE 0: MASTER CONTEXT & ARCHITECTURE SETUP (วางกฎเหล็กให้ AI ก่อนเริ่ม)
--------------------------------------------------------------------------------
เป้าหมาย: กำหนด Architecture, กฎของระบบ และป้องกันไม่ให้ AI เขียนโค้ดหลุดพอร์ตหรือผิดทิศทาง

[PROMPT]
คุณคือ Senior Full-stack Developer ที่เชี่ยวชาญ FastAPI และ Tailwind CSS
เรากำลังจะสร้างเว็บแอปพลิเคชัน "Smart PO & Invoice Auditor" 
สำหรับฝ่ายจัดซื้อและบัญชี เพื่อใช้ตรวจเช็คคำสั่งซื้อในระบบ (PO) ชนกับใบแจ้งหนี้/สัญญา PDF ของคู่ค้า

ข้อมูลในโปรเจกต์ที่มีให้แล้ว:
- ฐานข้อมูล SQLite: enterprise.db (มีตาราง vendor_master และ purchase_orders)
- โฟลเดอร์เอกสารคู่ค้า: sample_documents/ (มีไฟล์ PDF 4 เคส: Case1 ถึง Case4)
- คู่มือกฎสภาพแวดล้อม: AGENTS.md

กฎเหล็กทางสถาปัตยกรรม (ห้ามละเมิดเด็ดขาด):
1. Single-Port Architecture: ระบบต้องรันบน Port 8000 พอร์ตเดียวเท่านั้น และต้อง Bind host 0.0.0.0
2. ใช้ FastAPI เป็นตัวเสิร์ฟทั้ง Backend API และหน้าเว็บ UI (HTML/Tailwind) ในพอร์ตเดียวกัน
3. Subpath Proxy Rule: ในฝั่ง Frontend (HTML/JS) เวลา fetch API ต้องใช้ Relative Path เสมอ เช่น fetch('./api/...') ห้ามใส่ root slash นำหน้าเด็ดขาด (/api/...)
4. ใช้ pypdf สำหรับสกัดข้อความจากเอกสาร PDF
5. จัดการ package ด้วย uv และสร้าง run.sh สำหรับรันแอปพลิเคชัน

ตอบรับว่าเข้าใจข้อกำหนดทั้งหมด แล้วรอรับคำสั่งใน Sprint 1 ได้เลย
[/PROMPT]

STAGE 1: SPRINT 1 — DATABASE EXPLORER & SKELETON (เชื่อมต่อฐานข้อมูล PO)
--------------------------------------------------------------------------------
เป้าหมาย: อ่านข้อมูลจาก enterprise.db และแสดงผลบนหน้าเว็บใน Port 8000

[PROMPT]
มาเริ่ม Sprint 1 กัน: สร้างโครงสร้างโปรเจกต์และเชื่อมต่อฐานข้อมูล SQLite
สิ่งที่ต้องทำ:
1. สร้างไฟล์ database.py เพื่อเชื่อมต่อ enterprise.db โดยมีฟังก์ชัน:
   - get_all_pos(): ดึงรายการ PO ทั้งหมด (po_number, project_site, approved_amount)
   - get_po_detail(po_number): ดึงข้อมูล PO พร้อม Join กับ vendor_master (ดึง tax_id, vendor_name, bank_name, bank_account, scope_of_work, approved_amount, standard_credit_days)

2. สร้าง FastAPI app ใน main.py หรือ app.py พร้อม endpoint:
   - GET /api/pos: คืนรายชื่อ PO ทั้งหมด
   - GET /api/pos/{po_number}: คืนรายละเอียดข้อมูลจัดซื้อของ PO นั้น
   - GET /: เสิร์ฟหน้า index.html

3. สร้างหน้าเว็บ UI (index.html) สไตล์ Modern Enterprise Dashboard ด้วย Tailwind CSS:
   - Header ด้านบน: ชื่องาน "Smart PO & Invoice Auditor", โลโก้, สถานะระบบ Port 8000
   - กล่องเลือก PO (Dropdown Select) ที่ดึงรายการ PO ทั้งหมดจาก SQLite
   - เมื่อผู้ใช้เลือก PO ให้แสดง "การ์ดข้อมูลจัดซื้อในระบบ (PO Master Data)":
     * เลขที่ PO และ ชื่อโครงการ/ไซต์งาน
     * ชื่อคู่ค้าที่ถูกต้อง (Registered Vendor)
     * เลขประจำตัวผู้เสียภาษี 13 หลัก (Official Tax ID)
     * บัญชีธนาคารทางการ (Bank Name & Account)
     * วงเงินที่อนุมัติ (Approved Budget THB)
     * เครดิตเทอมมาตรฐาน (Standard Credit Terms)
     * ขอบเขตงานจัดซื้อ (Scope of Work)

ทดสอบรันบน Port 8000 และตรวจสอบว่าดึงข้อมูล PO จาก enterprise.db ขึ้นมาแสดงได้ถูกต้อง
[/PROMPT]

STAGE 3: SPRINT 3 — SMART AI AUDIT ENGINE (สมองกลตรวจจับ 4 จุดดัก)
--------------------------------------------------------------------------------
เป้าหมาย: ตรวจจับจุดผิดปกติทั้ง 4 มิติ และแสดงป้ายสถานะ 🟢/🟡/🔴

[PROMPT]
ตอนนี้เราจะสร้างหัวใจสำคัญของระบบใน Sprint 3: "AI Anomaly Audit Engine"
ให้เขียนตรรกะตรวจเช็คความถูกต้องระหว่างข้อมูล PO ในระบบ กับข้อความในบิล PDF โดยต้องจับจุดผิดปกติ 4 มิติสำคัญดังนี้:

1. ตรวจสอบยอดเงินและค่าบริการงอก (Scope & Extra Charges Trap):
   - เทียบ Subtotal ในบิลกับ approved_amount ใน PO
   - ตรวจว่ามีรายการแทรกแปลกปลอมนอกเหนือจาก PO หรือไม่ (เช่น Emergency fee, Mobilization)
   - หากมี ให้คำนวณยอดงอก (Extra Amount THB) และแจ้งเตือนให้ตัดออก

2. ตรวจสอบเงื่อนไขการส่งมอบงานและค่าปรับล่าช้า (Delay Penalty Clause):
   - อ่านวันกำหนดส่งงานตามสัญญาเทียบกับวันที่ส่งมอบจริง
   - ตรวจเงื่อนไขค่าปรับ: หากส่งมอบล่าช้าเกิน 7 วัน ให้คิดค่าปรับ 0.1% ต่อวันของมูลค่า PO
   - คำนวณยอดเงินค่าปรับที่ต้องหัก (Liquidated Damages THB)

3. ตรวจสอบความถูกต้องของคู่ค้าและบัญชีธนาคาร (Fraud & Diversion Alert):
   - ตรวจสอบ Tax ID บนบิลว่าตรงกับ vendor_master หรือไม่
   - ตรวจสอบชื่อธนาคารและเลขที่บัญชีว่าตรงกับ vendor_master หรือไม่
   - หากไม่ตรงเด็ดขาด: ต้องตีเป็น "🔴 CRITICAL / FRAUD ALERT" และสั่งระงับการจ่ายเงินทันที

4. ตรวจสอบการเบิกเงินตามงวดงาน (Over-milestone Billing Trap):
   - ตรวจสอบเปอร์เซ็นต์งวดงานที่ขอเบิก เช่น ขอเบิก 50%
   - ตรวจสอบเงื่อนไขสัญญาว่างวดปัจจุบันให้เบิกได้สูงสุดกี่เปอร์เซ็นต์ (เช่น งวด 1 ให้เบิกได้ 30%)
   - หากขอเบิกเกินสิทธิ์ ให้แจ้งเตือนยอดเงินส่วนเกินที่ยังจ่ายไม่ได้

การแสดงผลสถานะ:
- 🟢 APPROVED: ข้อมูลถูกต้อง 100% ไม่มีค่าปรับ ไม่มียอดงอก อนุมัติจ่ายเต็มจำนวน
- 🟡 WARNING: พบข้อผิดพลาดที่แก้ไขได้ (มียอดงอก, ส่งงานช้าต้องหักค่าปรับ, หรือขอเบิกเกินงวดงาน) แนะนำยอดจ่ายสุทธิที่ปรับแก้แล้ว
- 🔴 FRAUD ALERT: เลข Tax ID หรือเลขบัญชีธนาคารไม่ตรง ระงับการจ่ายเงินทันที

คำนวณและสรุปยอดเงิน:
- ยอดเงินตาม PO: xxx บาท
- หักยอดงอกนอก PO: xxx บาท
- หักค่าปรับส่งมอบล่าช้า: xxx บาท
- ยอดเงินที่อนุมัติจ่ายจริง (Net Payable Excl. VAT): xxx บาท
- VAT 7%: xxx บาท
- ยอดจ่ายรวมสุทธิ: xxx บาท
